### Улучшаем класс Audio, добавив в него инкапсуляцию

Класс в C++ объединяет данные (поля) и функции для работы с ними (методы). Описание класса принято делить на две части: заголовочный файл (.h) с объявлением структуры класса и файл реализации (.cpp) с кодом методов.

Данные и методы класса имеют модификаторы доступа. Возможны три модификатора: `private`, `protected` и `public`.
Члены класса с модификатором `private` доступны только внутри самого класса.
Члены класса с модификатором `protected` доступны внутри самого класса и классам-потомкам (будет рассмотрено позднее).
`Public`-члены класса доступны всем.

Пример объявления класса (файл audio.h):

```cpp
#ifndef AUDIO_H
#define AUDIO_H

#include <string>

class Audio {
private:
    // Приватные поля (доступны только методам самого класса)
    std::string title;
    std::string author;
    int year;

public:
    // Конструктор по умолчанию
    Audio() {
        title = "Unknown";
        author = "Unknown";
        year = 2026
        year = 2026;
    }

    // Конструктор с параметрами (использует список инициализации)
    Audio(const std::string& audioTitle, const std::string& audioAuthor, int audioYear) {
        title = audioTitle;
        author = audioAuthor;
        year = audioYear;
    }

    // --- Сеттеры (Setters) ---
    void setTitle(const std::string& audioTitle) {
        title = audioTitle;
    }

    void setAuthor(const std::string& audioAuthor) {
        author = audioAuthor;
    }

    void setYear(int audioYear) {
        year = audioYear;
    }

    // --- Геттеры (Getters) ---
    std::string getTitle() const {
        return title;
    }

    std::string getAuthor() const {
        return author;
    }

    int getYear() const {
        return year;
    }
};

#endif  // AUDIO_H
```

Поля `title`, `author` и `year` скрыты внутри класса. Это реализует принцип инкапсуляции.
Прямой доступ к ним извне запрещен (`track.title = "Song"` вызовет ошибку).
Это защищает данные от случайного изменения и позволяет контролировать, как именно объект используется.

Для того чтобы получить доступ (записать или считать) к закрытым данным используются
специальные методы сеттеры и геттеры.

**Сеттеры** — это публичные методы для изменения приватных полей (например, `setTitle`).
Вместо прямого изменения переменной вы вызываете метод. Внутри сеттера можно поставить валидацию (проверку корректности).
Например, внутри setAuthor можно добавить проверку, чтобы имя автора не было пустой строкой или не содержало запрещенных символов.

**Геттеры** — это публичные методы для получения значений приватных полей (например, `getTitle`).
Они дают безопасный доступ к данным "только для чтения".
Обратите внимание на спецификатор `const` в конце геттеров (например, `std::string getTitle() const`).
Он гарантирует компилятору, что этот метод только читает данные и гарантированно не изменит состояние самого объекта.

**Конструктор** — это специальный метод, который вызывается автоматически при создании нового объекта.
Он инициализирует поля данных класса так, что объект не будет содержать "мусорных" или пустых данных сразу после создания.
В примере выше два конструктора: один позволяет создать пустой трек со значениями по умолчанию ("Unknown"),
а второй — сразу заполнить все поля нужной информацией при объявлении объекта.

Все методы в классе короткие, состоят из одной строки, поэтому их можно описать
прямо в объявлении самого класса. Так что файл `audio.cpp` создавать не требуется.
Если же методы большие, то их определения (тела) необходимо помещать в файл `.cpp`

### Помещаем чтение CSV-данных в отдельный класс

Для удобства работы с CSV-файлом и уменьшения кода в `MainWindow`,
мы можем переместить всю рутину в отдельный класс CsvReader.

Пример класса `CsvReader` (файл csvreader.h):

```cpp
#ifndef CSVREADER_H
#define CSVREADER_H

class CsvReader {
public:
    // Метод (функция), которая открывает поток данных (std::ifstream fin)
    void open(const std::string& filename);

    // Метод с помощью которого можно проверить, успешно ли открыт файл
    bool is_open() const;

    // Метод который читает содержимое файла и выдает готовый вектор аудиозаписей
    std::vector<Audio> readAll();

private:
    // Объект файлового потока хранится в самом классе
    std::ifstream fin;
};

#endif  // CSVREADER_H
```

Пример реализации методов класса CsvReader (файл csvreader.cpp)


### Сигналы и слоты Qt

Каждый виджет (widget) Qt может генерировать сигналы и может содержать специальные
функции -- слоты, которые эти сигналы могут ловить.

Например, QLineEdit (виджет, позволяющий вводить одну строку текста) имеет
сигнал `editingFinished()`, который генерируется всякий раз, когда пользователь закончил
ввод (нажал на Enter, или LineEdit потерял фокус ввода).

Для того чтобы в `MainWindow` поймать этот сигнал и обработать, необходимо создать слот:
объявить его внутри класса (в mainwindow.h)

```cpp
public slots:  // все слоты должны быть под модификатором slots
    void search();
```

и описать его поведение (в mainwindow.cpp)

```cpp
void MainWindow::search()
{
    // Поиск данных
    // ....
}
```

Для того чтобы нужный слот запускался при получении конкретного сигнала, их надо соединить.
Обычно соединение выполняется в конструкторе окна MainWindow:

```cpp
MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent)
    , ui(new Ui::MainWindow)
{
    ui->setupUi(this);  // Это оставляем без изменений

    // Соединяем сигнал editionFinished() объекта editSearch
    // и слот search() объекта this (самого окна MainWindow)
    connect(ui->editSearch, &QLineEdit::editingFinished, this, &MainWindow::search);

    // .... остальной код
}
```

Таким образом, функция MainWindow::search будет запускаться каждый раз когда
пользователь введет что-либо в поле `QLineEdit`.
