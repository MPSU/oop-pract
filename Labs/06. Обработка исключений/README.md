# Лабораторная работа 6: Обработка исключений

## 1. Краткая теоретическая справка

### Исключения

Исключения в C++ -- это механизм для обработки ошибок, которые возникают
**во время выполнения программы** (**runtime errors**).
Он позволяет отделить код обнаружения ошибки от кода её обработки.
Управление исключениями строится вокруг трех ключевых слов:

| Ключевое слово | Описание |
|---|---|
| `throw` | Используется для генерирования (выброса) исключения, когда обнаружена ошибка |
| `try` | Обозначает блок кода, в котором может возникнуть исключение |
| `catch` | Обозначает блок обработки исключения. Вызывается, если тип выброшенного исключения совпадает с типом, указанным в параметрах `catch` |

Базовый пример кода

```cpp
#include <iostream>
#include <stdexcept> // Содержит объявления классов стандартных исключений

double divide(double a, double b)
{
    if (b == 0.0) {
        // Выбрасываем исключение и функция на этом завершается
        throw std::invalid_argument("Деление на ноль!");
    }

    return a / b;
}

int main()
{
    try {  // Пробуем выполнить код
        std::println("Результат деления: {}", divide(10.0, 0.0));
    } 
    // Ловим конкретную ошибку, которая может возникнуть
    catch (const std::invalid_argument& e) {
        // Выводим сообщение в консоль
        std::println(std::cerr, "Ошибка: {}", e.what());
    }
    return 0;
}
```

### Типы исключений

Передать через `throw` можно объект любого типа (число, строку, пользовательский класс).
Однако хорошей практикой считается генерировать объекты классов, унаследованных от стандартного std::exception.

```cpp
throw 5;                                        // Целочисленное исключение
throw std::string("Ошибка!");                   // Исключение строкового типа
throw std::runtime_error("Ошибка выполнения!"); // Исключение runtime
```

Ловить исключения можно также разных типов, добавляя блоки `catch` друг за другом.

```cpp
try {
    // Здесь код который может вернуть исключения разных типов,
    // в случае разных ошибок
}
catch (int er) {
    // Обработка ошибки типа int
    std::println("Код ошибки {}", er);
}
catch (const std::string& er) {
    // Обработка ошибки типа std::string
    std::println("Ошибка! {}", er);
}
catch (const std::invalid_argument& e) {
    std::println(std::cerr, "Ошибка: {}", e.what());
}
catch (...) {
    // Обработка любых исключений, которые не были обработаны ранее
}
```

Блок `catch (...)` (с тремя точками) перехватывает абсолютно любые исключения. Его обычно ставят в самом конце.


### Механизм раскрутки стека (Stack Unwinding)

Когда генерируется исключение, C++ выходит из текущей функции и уничтожает все локальные объекты
(вызываются их деструкторы), пока не найдет подходящий блок `catch`.
Если нужного блока `catch` нет, то программа будет аварийно закрыта и выведено сообщение в консоль
об исключении.

```cpp
#include <iostream>
#include <stdexcept> // Содержит объявления классов стандартных исключений

double divide(double a, double b)
{
    if (b == 0.0) {
        throw std::invalid_argument("Деление на ноль!");
    }
    return a / b;
}

double calc(double x)
{
    // ... делаем вычисления и потом вызываем divide()

    double r = divide(5.0, x);  // Будет выброшено исключение
    // и остальная часть функции выполнена не будет

    std::println("Result = {}", r);
    return r;
}

int main()
{
    try {  // Пробуем выполнить код
        calc(0.0);
    } 
    catch (const std::invalid_argument& e) {
        std::println(std::cerr, "Ошибка: {}", e.what());
    }
    return 0;
}
```

Исключения принято перехватывать по константной ссылке (const Exception& e),
чтобы избежать лишнего копирования объектов и эффекта "срезания" типов (object slicing).


### Стандартная библиотека и класс std::exception

`std::exception` -- это базовый класс для всех стандартных исключений в C++, определенный в заголовочном файле <exception>.
Он служит основой для построения иерархии встроенных и пользовательских типов ошибок.

Главная цель `std::exception` -- предоставить единый интерфейс для получения информации об ошибке с помощью виртуального метода `what()`.

Виртуальный метод `what()` должен возвращать текст с описанием ошибки и объявляется следующим образом:

```cpp
virtual const char* what() const noexcept
```

Стандартная библиотека C++ содержит несколько классов-наследников `std::exception`,
которые можно разделить на две основные группы в зависимости от природы ошибки.
Основные классы из заголовка `<stdexcept>` представлены в таблице:

| Базовый класс | Производные классы | Описание ошибки |
|---|---|---|
| `std::logic_error` (Логические ошибки в логике программы, которые можно предотвратить) | `std::invalid_argument` `std::out_of_range` `std::length_error` `std::domain_error` | Передача неверного аргумента; Выход за границы диапазона (например, в `std::vector`); Превышение максимального размера объекта; Выход за область определения математической функции |
| `std::runtime_error` (Ошибки выполнения, которые сложно или невозможно предсказать) | `std::overflow_error` `std::underflow_error` `std::range_error` | Арифметическое переполнение; Потеря значимости (исчезновение порядка); Ошибка диапазона внутренних вычислений |
| Другие прямые наследники (Специфические системные исключения) | `std::bad_alloc` `std::bad_cast` `std::bad_typeid` | Ошибка выделения динамической памяти; Ошибка при неверном `dynamic_cast` по ссылке; Ошибка при применении `typeid` к нулевому указателю |

Также от `std::exception` можно наследовать свой класс исключений и переопределить функцию `what()`.
Например, так:

```cpp
#include <exception>
#include <string>

class MyException : public std::exception {
private:
    std::string message_;
    unsigned code_;
    std::string what_;

public:
    MyException(const std::string& msg, unsigned code)
        : message_(msg),
          code_(code),
          what_(std::to_string(code_) + ": " + message_) {}

    const char* what() const noexcept override {
        return what_.c_str();
    }

    unsigned code() const noexcept {
        return code_;
    };
};
```


#### Пример: `std::stoi`

Функция `std::stoi` может выбросить два типа исключений
(оба являются наследниками `std::logic_error` и `std::runtime_error`),
если строку не удается преобразовать в целое число:

| Исключение | Причина выброса | Пример строки |
|---|---|---|
| `std::invalid_argument` | Строка не содержит символов, которые можно интерпретировать как число | "abc", " hello", "" |
| `std::out_of_range` | Число в строке корректно, но оно выходит за границы диапазона типа int | "99999999999999", "-2147483649" |

*Примечание:* Если строка начинается с цифр, но заканчивается буквами (например, "123xyz"),
`std::stoi` успешно вернет 123 и не выбросит исключение.


### Пробрасывание ошибки и трансформация исключений

Иногда имеет смысл поймать низкоуровневое исключение (например, `std::invalid_argument` при обработке `std::stoi`)
и выбросить вместо него высокоуровневое бизнес-исключение (например, `MyException`), используя инициализацию нового объекта.

В низкоуровневом обработчике данных ловим низкоуровневые ошибки:

```cpp
void processData()
{
    // ...
    try {
        // Обрабатываем строку, может быть выброс std::invalid_argument
        processLine();
    }
    catch (const std::invalid_argument& ex) {
        throw MyException("Ошибка обработки данных", 67);
    }
}
```

В высокоуровневом (в `MainWindow`) ловим `MyException` и показываем в `textBrowser`:

```cpp
void MainWindow::process()
{
    try {
        processData();
    }
    catch (const MyException& ex) {
        int code = ex.code();
        QString text(ex.what());

        ui->textBrowser->append(QString("Ошибка %1: %2").arg(code, text));
    }
}
```
