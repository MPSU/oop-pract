# Лабораторная работа 7: Перегрузка операторов

## 1. Краткая теоретическая справка

Перегрузка операторов в C++ -- это возможность изменить поведение стандартных операторов
(таких как `+`, `-`, `*`, `==`, `<<` и др.) для пользовательских типов данных (классов и структур).
Она позволяет работать с объектами классов так же просто и интуитивно, как и со встроенными типами (например, `int` или `double`).


### Виды операторов

Основные операторы в C++:

* Присваивание
`a = b` `a += b` `a -= b` `a *= b` `a /= b` `a %= b` `a &= b` `a |= b` `a ^= b` `a <<= b` `a >>= b`

* Инкремент / Декремент
`++a` `--a` `a++` `a--`

* Арифметические
`+a` `-a` `a + b` `a - b` `a * b` `a / b` `a % b` `~a` `a & b` `a | b` `a ^ b` `a << b` `a >> b`

* Логические
`!a` `a && b` `a || b`

* Сравнения
`a == b` `a != b` `a < b` `a > b` `a <= b` `a >= b` `a <=> b`

* Доступ к членам класса
`a[...]` `*a` `&a` `a->b` `a.b` `a->*b` `a.*b`

* Другие
`a(...)` (вызов функции) `a, b` (запятая) `a ? b : c` (условный)

По количеству операндов можно выделить унарные (`a++`, `-a`, и др.),
бинарные (`a + b`, `a << b` и др.) и тернарные (`a ? b : c`).


### Описание

Перегрузка реализуется с помощью специальной функции, имя которой состоит
из ключевого слова `operator` и самого знака оператора (например, `operator+`).
Перегрузить оператор можно двумя способами:

1. Как метод класса -- левый операнд автоматически является текущим объектом (`this`).

2. Как внешнюю (обычную или дружественную `friend`) функцию -- оба операнда передаются в качестве аргументов.

Когда оператор встречается в выражении, и хотя бы один из его операндов является классом (структурой),
то запускается механизм определения пользовательской функции, которая должна быть вызвана на месте оператора.
При этом компилятор руководствуется следующими правилами:

| Выражение | Функция-член класса | Внешняя функция | Пример |
| :-- | :-- | :-- | :-- |
| `@a`      | `(a).operator@ ( )`    | `operator@ (a)`    | `!std::cin` вызовет `std::cin.operator!()` |
| `a@b`     | `(a).operator@ (b)`    | `operator@ (a, b)` | `std::cout << 42` вызовет `std::cout.operator<<(42)` |
| `a=b`     | `(a).operator= (b)`    | не может быть не-членом класса | Для `std::string s;`, `s = "abc";` вызовет `s.operator=("abc")` |
| `a(b...)` | `(a).operator()(b...)` | не может быть не-членом класса | Для `std::random_device r;`, `auto n = r();` вызовет `r.operator()()` |
| `a[b...]` | `(a).operator[](b...)` | не может быть не-членом класса | Для `std::map<int, int> m;`, `m[1] = 2;` вызовет `m.operator[](1)` |
| `a->`     | `(a).operator->( )`    | не может быть не-членом класса | Для `std::unique_ptr<S> p;`, `p->bar()` вызовет `p.operator->()` |
| `a@`      | `(a).operator@ (0)`    | `operator@ (a, 0)` | Для `std::vector<int>::iterator i;`, `i++` вызовет `i.operator++(0)` |


### Правила перегрузки

* Нельзя создавать новые символы операторов (например, нельзя перегрузить `**`).
* Нельзя менять приоритет и ассоциативность операторов.
* Нельзя изменить поведение операторов для встроенных типов (например, переопределить `int + int`).
* Четыре оператора нельзя перегрузить в принципе: `.`, `.*`, `::`, `?:`.


### Примеры реализации

Кроме ограничений выше, C++ не определяет что перегруженный оператор должен делать,
или какой у него возвращаемый тип (он не участвует в определении перегрузки),
но в целом ожидается что перегруженные операторы будут вести себя максимально похоже
на встроенные операторы: `operator+` будет складывать а не умножать аргументы,
`operator=` будет присваивать и т.п. Связанные операторы должны вести себя одинаково
(`operator+` и `operator+=` выполняют похожие операции сложения).
Возвращаемые типы данных должны определяться выражениями в которых они используются:
например, оператор присваивания возвращает ссылку, для того чтобы можно было написать
`a = b = c = d`, потому что встроенные операторы делают именно так.

Основные перегрузки операторов имеют следующие, канонические реализации:

#### Оператор присваивания

Оператор присваивания `operator=` применяется при выполнении копирования или перемещения.
Каноническая реализация делает проверку на самоприсваивание и возвращает левый операнд (`lhs`) по ссылке:

```cpp
// Метод класса; не может быть внешней функцией
// Левый операнд -- this, правый -- T
T& operator=(const T& other)
{
    // Защита от присваивания себе
    if (this == &other)
        return *this;

    // реализация копирования
    
    return *this;
}
```


#### Оператор вставки в поток

Операторами вставки и извлечения из потока называют перегруженные операторы
`operator>>` и `operator<<` используемые с объектами `std::istream&` или `std::ostream&`
в качестве левого операнда. Так как они используются с пользовательским типом данных
справа (`b` в `a @ b`), то они должны быть реализованы как внешние функции:

```cpp
//  Внешняя функция
std::ostream& operator<<(std::ostream& os, const T& obj)
{
    // вывод теста в поток os
    os << obj.a << ", " << obj.b << std::endl;

    return os;
}
```

Иногда эти операторы реализуют как дружественные функции.


#### Инкремент и декремент

Когда в выражении встречается постфиксный инкремент или декремент, вызывается соответствующая функция (`operator++` или `operator--`)
с числом 0 в качестве аргумента. Обычно он объявляется как `T operator++(int)` или `T operator--(int)`,
при этом аргумент игнорируется. Чаще всего постфиксные операторы инкремента и декремента реализуются через префиксные эквиваленты:


```cpp
// 
// Префиксный инкремент
T& operator++()
{
    // Здесь делаем сам инкремент
    return *this; // Возвращаем новое значение по ссылке
}
  
// Постфиксный инкремент
T operator++(int)
{
    T old = *this; // Сохраняем старое значение во временную переменную
    operator++();  // Инкрементируем
    return old;    // Возвращаем старое значение
}
```


#### Бинарные арифметические операторы

Обычно бинарные операторы реализуются как внешние функции для симметрии (например, реализация сложения
комплексного числа и простого числа должна работать как "комплексное + число" и как "число + комплексное").
Так как для каждого арифметического оператора существует соответствующий оператор составного присваивания,
канонические формы бинарных операторов реализуются через них:

```cpp
class T {
public:
    T& operator+=(const T& rhs) // составное присваиние (не обязано быть членом класса,
    {                           // но часто является, для изменения закрытых свойств)
        /* здесь просиходит добавление rhs к *this */
        return *this;  // возвращаем результат по ссылке
    }
    
    // дружественная функция обявленная в теле класса является встраиваемой
    friend T operator+(const T& lhs, const T& rhs)
    {
        T tmp(lhs);  // создаем новый объект-копию lhs
        tmp += rhs;  // искользуем уже готовое составное присваивание
        return tmp;  // возвращаем по значению (задействуется перемещающий конструктор)
    }
};
```


#### Операторы сравнения

Алгоритмы стандартной библиотеки, такие как `std::sort` предполагают наличие
операторов сравнения `operator<` для пользовательских типов.

```cpp
class T {
    int x, y;

public:
    friend bool operator<(const T& lhs, const T& rhs)
    {
        /* возвращаем true, если `x` левого операнда меньше правого
           и `y` левого оператора меньше правого */
        return (lhs.x < rhs.x) && (lhs.y < rhs.y);
    }
};
```

Обычно, если есть один оператор `operator<`, то и другие операторы сравнения тоже должны быть реализованы.


#### Оператор логической инверсии

Оператор логической инверсии `operator!` имеет смысл перегружать для классов, которые используются
в логических выражениях. Например, для класса подключения к серверу:

```cpp
class Client {
public:
    bool is_connected() const {
        // Возвращает true, если успешно подключено к серверу
    }

    bool operator!() const {
        return !is_connected();
    }
};
```

Теперь в коде эту перегрузку можно использовать следующим образом:

```cpp
Client cli("server.ru");
if (!cli) {
    std::println("Не удалось подключиться к серверу");
}
```
